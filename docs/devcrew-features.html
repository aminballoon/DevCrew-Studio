ปัญหาที่ DevCrew แก้

"AI บอกว่าเสร็จ แต่ไม่จริง"

Verify เป็นโค้ดธรรมดา ไม่ใช่ AI ใช้รันเทสต์จริง ล็อกไฟล์เทสต์ด้วย SHA-256 และเช็กว่าเทสต์ที่ประกาศไว้ได้รันครบทุกข้อ ถ้าไม่ผ่าน Dev ต้องกลับไปแก้

"AI แก้เทสต์ให้ตัวเองผ่าน"

Dev ไม่มีสิทธิ์เขียน tests/ หรือ contracts/ และหลังทุก turn ระบบจะ snapshot workspace แล้ว revert ไฟล์ที่แก้นอกขอบเขต รวมถึงไฟล์ที่แก้ผ่าน shell

"ไม่รู้ว่า AI ทำอะไรไปบ้าง"

ทุก event ถูกบันทึกเป็น log ได้แก่ tool call, token, ค่าใช้จ่ายแยกบทบาท, diff และผล verify ดูย้อนหลังและตรวจสอบได้

"อยากให้คนคุมจุดสำคัญ"

มี gate ให้อนุมัติแผนก่อนเขียนโค้ด และอนุมัติโค้ดก่อน commit ถ้าวนแก้ไม่ผ่านจะส่งไปที่ escalation gate ให้คนตัดสินใจ

Feature หลัก

ควบคุม

Guardrails

  • แต่ละบทบาทเขียนได้เฉพาะ path ของตัวเอง
  • Snapshot แล้ว revert ไฟล์ที่แก้นอกขอบเขตหลังทุก turn
  • ล็อกเทสต์ด้วย hash และนับจำนวนเทสต์ที่รันจริง
  • จำกัดรอบวนแก้, จำกัดการวางแผนใหม่ไว้ 2 รอบ และตั้ง time limit
คนในวงจร

Human gates ทุกช่องทาง

  • Dashboard: ปุ่ม Approve, Revise, Abort, Retry และ Replan
  • Discord DM พร้อมปุ่มกด อนุมัติจากมือถือได้ (ทดสอบกับ bot จริงแล้ว)
  • Webhook ไปยัง chat agent อื่นได้ เช่น OpenClaw, Hermes ไปจนถึง Telegram/WhatsApp (ยังไม่ได้ลองกับของจริง)
  • ใช้ CLI ได้: gate <runId> approve
ยืดหยุ่น

Pipeline เป็นไฟล์

  • ออกแบบ pipeline ได้เองด้วย JSON มี schema และ validator
  • pipeline ใหม่ต้องให้คนอนุมัติก่อนใช้
  • Skill /new-pipeline ให้ Claude ร่าง pipeline จากคำขอภาษาคน
  • Role guide 13 แบบ เช่น risk-planner, test-engineer, security-auditor, firmware-reviewer และ hil-rig-engineer
หลายค่าย

Agent ข้ามค่ายผ่าน ACP

  • Claude, Codex, Gemini (Antigravity) หรือ agent ใดก็ได้ที่รองรับ ACP
  • เลือกโมเดลแยกตามบทบาทได้ เช่น ให้ QA และ Reviewer ใช้คนละค่ายกับ Dev
  • ใช้ login ของ CLI ของแต่ละค่าย ระบบไม่ได้ถือ token เอง
  • Fake agent แบบ scripted ช่วยทดสอบโดยไม่เสียโควต้า
มองเห็น

Dashboard แบบสด

  • แผนภาพ pipeline ที่แสดง node ที่กำลังทำ, fix loop และเส้นทางส่งกลับ
  • Token และค่าใช้จ่ายแยกบทบาท, ฟีดกิจกรรม และ diff แบบมีสี
  • PRD, สัญญา และสถาปัตยกรรมระดับไฟล์ที่ Gate 1
  • Resume run ข้าม process (SQLite checkpoint) ใช้บนมือถือได้ และรองรับ dark mode
วัดผล

Benchmark harness ในตัว

  • Hidden tests ที่คัดลอกเข้าไปตอนตรวจเท่านั้น และสุ่มลำดับการรัน
  • Evolution rounds และ handoff เพื่อวัดว่าโค้ดต่อยอดง่ายแค่ไหน
  • รายงานจุดที่ pipeline เสียเวลาหรือเงิน ใช้ปรับปรุงระบบต่อ
  • ทนต่อโควต้าหมด: รอแล้วรันซ้ำให้เอง
โลกจริง

Firmware และ Hardware-in-the-loop

  • Preset firmware-board และ system-integration
  • Verify อ่านผลเทสต์ได้หลายภาษา: Node, pytest, Unity/PlatformIO, GoogleTest, cargo, go, TAP และบรรทัด HIL
  • ทดสอบบนบอร์ด ESP32-S3 จริง มีตัวล็อกพอร์ต USB
โหมดงาน

Preset ที่อนุมัติแล้ว 10 แบบ

  • minimal: งานเล็ก ราคาถูก
  • standard: มี reviewer และ gate สองด่าน
  • with-security: เพิ่ม Semgrep และ security audit
  • blind QA: Dev ไม่เห็นเทสต์จริง
  • existing-code: วิเคราะห์โค้ดเดิมก่อนแก้
  • with-docs: เขียนคู่มือการใช้งานให้หลังผ่านรีวิว

ทำไมต้อง DevCrew

1. ความไว้ใจที่พิสูจน์ได้

ไม่ต้องเชื่อว่า AI ซื่อสัตย์ ระบบออกแบบให้มันโกงไม่ได้ตั้งแต่ต้น เทสต์ถูกล็อก การเขียนไฟล์มีขอบเขต และคนที่ตัดสินว่างานเสร็จไม่ใช่ AI

2. คนยังคุมจุดสำคัญ

AI ทำงานส่วนใหญ่ คนอนุมัติแค่แผนและผลลัพธ์ ทำจากมือถือได้ จึงไม่ต้องนั่งเฝ้า

3. ไม่ผูกกับเจ้าใดเจ้าหนึ่ง

สลับโมเดลได้ตามบทบาท ใช้โมเดลถูกกับงานง่าย และใช้คนละค่ายตรวจงานกันเองได้

4. วัดได้และปรับได้

มี benchmark ในตัว ทำให้ตัดสินใจจากข้อมูลจริง และใช้หาจุดอ่อนของ pipeline เองได้ เราหาบั๊กของระบบเจอและแก้ไปแล้วอย่างน้อย 7 ตัว

Roadmap: Task Router (ผู้ช่วยเลือกรูปแบบทีม) ยังไม่ได้สร้าง

ทีมเต็มรูปแบบไม่ได้คุ้มกับทุกงาน ขั้นต่อไปจึงเป็นตัวช่วยประเมินงานก่อนเริ่ม ว่าควรใช้ AI ตัวเดียว ใช้ทีมเล็ก หรือใช้ทีมเต็ม หรือไม่ต้องแบ่งทีมเลย แค่ให้ QA เขียนเทสต์ล็อกไว้ก่อนก็พอ เกณฑ์ตั้งต้นมาจากผล benchmark ของเราเอง

ลักษณะงานโหมดที่แนะนำหลักฐาน
สเปกชัด มีเทสต์รันในเครื่องได้ และเสี่ยงต่ำSingle agent6 การทดลองซอฟต์แวร์: คุณภาพเท่ากัน และถูกกว่า 5–50×
สเปกชัด แต่ต้องการหลักฐานว่าเทสต์ไม่ถูกแก้Test-first: QA เขียนเทสต์แล้วล็อก จากนั้นให้ AI ตัวเดียวทำ ปิดด้วย Verifyได้การรับประกันของทีมในต้นทุนที่ใกล้ Single (ยังต้องวัด)
สเปกกำกวม หรือมีจุดที่ต้องให้คนตัดสินMinimal team + Gate 1IT-01: ทีมหยุดแล้วถามคนเมื่อเทสต์ขัดกับสเปก
งานเสี่ยงสูงหรือเปิดสู่อินเทอร์เน็ตwith-securitySemgrep และ audit เป็นหลักฐานที่ตรวจย้อนได้
ตรวจผลในเครื่องไม่ได้ (hardware หรือระบบภายนอก)Team + HIL VerifyHW-01: Single ผ่านไม่สม่ำเสมอ (ผลชุดใหม่กำลังวัด)

ตัวตัดสิน: งานนี้เป็นการจำแนกประเภท ไม่ได้ต้องสร้างข้อความ จึงเหมาะกับโมเดลตัดสินใจโดยเฉพาะ เช่น Jev ของ TypeSafe AI ซึ่งออกแบบมาเพื่อตัดสินใจและจำแนกข้อมูลให้ซอฟต์แวร์ คาดว่าจะเร็วและถูกกว่าการให้ LLM ตัวใหญ่ประเมิน
Input: requirement, ขนาด codebase, ระดับความเสี่ยง และวิธีตรวจผล
Output: หนึ่งในห้าโหมดข้างบน
ยังไม่ได้ทดลองกับ Jev จริง และควรเทียบกับ baseline ที่เป็นกฎธรรมดา (rule-based) ด้วย

วิธีใช้ Jev ที่เหมาะ (จากเอกสารของ TypeSafe): อย่าถามคำถามใหญ่ข้อเดียวว่า "ควรใช้โหมดไหน" ให้แตกเป็นคำถามย่อยที่ตอบได้ทันที แล้วให้โค้ดของ DevCrew รวมคำตอบเป็นโหมด

  • Choice: "ผลลัพธ์ตรวจได้ด้วยการรันเทสต์ในเครื่องไหม" (ได้ / ต้องใช้ hardware / ต้องใช้คน)
  • Score: "สเปกนี้กำกวมแค่ไหน"
  • Score: "ถ้าผิดพลาด ความเสียหายรุนแรงแค่ไหน"
  • Choice: "เปิดสู่อินเทอร์เน็ตหรือจัดการข้อมูลอ่อนไหวไหม"

Jev ตอบกลับพร้อม confidence ถ้าความมั่นใจต่ำ ให้ระบบเลือกโหมดที่ปลอดภัยกว่าไว้ก่อน

Test case ที่ต้องทำเพื่อพิสูจน์ Router:

  • Router accuracy: ให้ Router เลือกโหมดของงานที่เราวัดไปแล้ว 15 งาน แล้วเทียบว่าตรงกับโหมดที่ชนะจริงหรือไม่
  • Routed vs fixed: รันชุดงานผสมแบบใช้ Router เทียบกับใช้ทีมทุกงาน และใช้ Single ทุกงาน วัดคุณภาพรวมและต้นทุนรวม เป้าหมายคือคุณภาพเท่าแบบทีม ในต้นทุนใกล้แบบ Single
  • Test-first mode: วัดว่าโหมด "QA ล็อกเทสต์ แล้วให้ AI ตัวเดียวทำ" ได้ความปลอดภัยแบบทีมในราคาใกล้ Single จริงหรือไม่
  • ความผิดพลาดของ Router: ถ้า Router เลือกโหมดถูกเกินไปกับงานเสี่ยง ต้องมีกลไกยกระดับเอง เช่น ถ้า Verify ไม่ผ่าน 2 ครั้ง ให้ขยับไปใช้ทีม

ข้อจำกัดที่ต้องบอก

  • สำหรับงานซอฟต์แวร์ทั่วไป ทีมแพงและช้ากว่า AI ตัวเดียวชัดเจน (ดูหน้าผล benchmark)
  • Chat gate ผ่าน OpenClaw/Hermes และ LangGraph Studio ยังไม่ได้ลองกับของจริง
  • Dashboard ไม่มีระบบ login และเปิดได้เฉพาะ 127.0.0.1
  • pipeline บางตัว (เช่น firmware) เพิ่งเจอบั๊กการอ่านผลเทสต์จากการทดสอบครั้งนี้ ต้องทดสอบกับงานจริงเพิ่ม
